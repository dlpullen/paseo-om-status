# Observational Memory Status Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use the
> `subagent-driven-development` skill (recommended) to implement this plan
> task-by-task via pi-subagents. Steps use checkbox (`- [ ]`) syntax for
> tracking.

**Goal:** Show a live, agent-scoped OM status pill and read-only popover in Paseo.

**Architecture:** Use Paseo 0.17.4's supported track-bar slot (approved in conversation). A Pi companion and daemon RPC read live OM status through a private launch-scoped Unix socket; the client never prompts Pi.

**Tech Stack:** TypeScript, Node IPC, Paseo plugin SDK 0.17.4, React Native, OM 3.1.4.

**Spec:** [HANDOFF.md](../../HANDOFF.md) and [verified host contracts](../paseo-0.17.4-compatibility.md).

## Global constraints

One pill; keep Paseo's existing context meter independent. No transcript rows, model turns, session file scanning, or Hindsight data. Never recompute OM metrics or substitute fixture or other-session data. Wide anchored surface and compact sheet use Paseo's built-in behavior. Use the approved track bar instead of modifying the host.

## Task 1: Live status contract and transport

- [x] Define `readStatus` in `shared/status.ts` with ready, unavailable and inapplicable results. Ready status binds metrics to a live Pi ID and revision.
- [x] In `pi/index.ts`, capture only the audited OM 3.1.4 status handler and call it with the active read-only context and an isolated `notify` sink. Keep the ordinary command unchanged. Decode only the handler's output in `pi/status-text.ts`.
- [x] In `index.server.ts` and `server/bridge.ts`, allocate a private socket for interactive Pi, validate the agent snapshot before and after sampling, and confirm the current socket generation and session identity. Exercise fixture parity, timeout, unsupported OM and identity mismatches.

## Task 2: Per-agent composer pill and popover

- [x] Register one pill per Pi agent via an owned SDK directory subscription in `index.client.tsx`.
- [x] Implement request sequencing, selection invalidation, unavailable and stale states in `client/status-state.ts`. Retain no numeric label after expiry or a known identity change.
- [x] Render all mockup sections and refresh in `client/status-popover.tsx` using the host theme and compact layout.

## Task 3: Verify and package

- [x] Use an isolated real Pi with OM. Compare all fields with the manual command in the same session and verify reads add no output, messages or turns. Switch Pi sessions and reject the old ID.
- [x] Load the plugin on a disposable Paseo 0.17.4 daemon. Exercise two agents; open and refresh on web at 1400 px and 390 px with the built-in context meter still reachable. Check the timeline does not change.
- [x] Document opt-in setup and verify the locally installed Pi 1.6.1 as well as the 0.84.2 fixture. Run `npm ci`, `npm run typecheck`, `npm test`, and `npm pack --dry-run --json`; verify runtime files and mockups are included.

Native iOS/Android clients were not exercised. The live daemon and Pi profile were not modified.
